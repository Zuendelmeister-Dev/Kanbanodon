# Kanbanodon 0.1.7

Release prepared on 9 October 2026. Image: `zuendelmeister/kanbanodon:0.1.7`.

## Changes

- Pan wide Boards by holding the left mouse button on the background and dragging horizontally, without finding the bottom scrollbar.
- Dependency inspection and Focus tasks retain every workflow status column, including empty columns and Done. Cards remain in their current status.
- Dependency order sorts tasks within their status columns. Normal order retains manual card dragging; buttons remain clickable while panning.
- Refresh browser assets using updated cache identifiers.
- Exclude local synchronization copies and browser test files from the container image.

No database migration is introduced by this release. Existing data volumes remain usable.

## Validate and build

Run from the repository root with Docker Desktop running in Linux-container mode:

```powershell
go test ./...
node --test web/static/*.test.js
git diff --check
docker build --platform linux/amd64 --build-arg VERSION=0.1.7 -t zuendelmeister/kanbanodon:0.1.7 .
```

This builds a Linux AMD64 image. It does not publish an ARM64 image or a multi-platform manifest.

## Git commit and push

Review the changes, then stage the release files explicitly. Local synchronization copies are preserved under the ignored `tmp/` directory and are excluded from the build.

```powershell
git add .gitignore .dockerignore Dockerfile README.md docs/task-tools.md docs/releases/0.1.7.md web/static/app.js web/static/app.test.js web/static/index.html web/static/styles.css
git diff --cached --check
git diff --cached --stat
git -c user.name="Zuendelmeister-Dev" -c user.email="Zuendelmeister-Dev@users.noreply.github.com" commit -F tmp/release/0.1.7-commit.txt
git push --set-upstream origin HEAD
```

If existing remote branches are replaced after anonymizing commit history, use reviewed explicit `--force-with-lease` values and an atomic push. A regular push of one new release branch does not replace the older history on other branches. Existing commit signatures become invalid when author metadata changes.

The commit message helper lives in the ignored `tmp/release/` directory. It is not included in Git or the image. The command uses the public project identity and GitHub Noreply email for this commit.

## Publish to Docker Hub

Repository: [zuendelmeister/kanbanodon](https://hub.docker.com/repository/docker/zuendelmeister/kanbanodon/general).

After validating the image and reviewing the Git changes:

```powershell
docker login
docker push zuendelmeister/kanbanodon:0.1.7
```

Only update the moving `latest` tag when 0.1.7 should become the default release:

```powershell
docker tag zuendelmeister/kanbanodon:0.1.7 zuendelmeister/kanbanodon:latest
docker push zuendelmeister/kanbanodon:latest
```

## Run the published image

Set a private session secret, then run:

```powershell
if ([string]::IsNullOrWhiteSpace($env:KANBANODON_SESSION_SECRET)) { throw "Set KANBANODON_SESSION_SECRET before starting the container." }
docker run -d --name kanbanodon --restart unless-stopped -p 127.0.0.1:8080:8080 -e KANBANODON_SESSION_SECRET="$env:KANBANODON_SESSION_SECRET" -v kanbanodon-data:/data zuendelmeister/kanbanodon:0.1.7
```

Back up existing application data before upgrading. To replace an existing container, stop and remove only the container, retain its named data volume, and recreate it with the same configuration and the 0.1.7 image.
